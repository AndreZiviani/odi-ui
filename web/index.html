    Transceiver

    The chip temperature is read from the SoC sensor. Its scale is not verified against a reference, so read it as a trend rather than an exact figure. The limits are set high on purpose, and nothing is shut down automatically: the page only warns.

    Forwarding

    Healthy looks like a mirror: what the fibre receives, the host side sends.

    Why rates, not totals

    Traffic crosses the switch in hardware, so these counters are the only place forwarding is visible. The fibre side counts without interruption; the host side is cleared by the performance-monitoring cycle every fifteen minutes. So the two running totals cannot be held against each other — only the rates, measured between two refreshes of this page, mirror.

        Why nothing here writes, and where the table list comes from
        
    omcicli mib set exists and is out of reach on purpose. The
           MIB is the OLT’s copy of the service and it is rebuilt at every
           re-registration, so a change made here would survive one reboot and
           not the next. Settings that persist are on Config.
    
        
    The table list is a capture, not a query: omcicli get tables
           returns nothing and leaves the stock omci_app unable to
           answer anything until it is restarted. This image’s omcid answers
           it safely, but the refusal stays for the stock slot.
    
      
    
    
    
  
    

  
  
    
    
    
      
      
      
      
    
    

    
    
    
      
    
      
    
        What committing means
        
    U-Boot boots the committed partition by default, every
           time: the one marked Committed above (sw_commit).
    
        
    A trial boot is one-shot. Trying a partition boots it once; the next
           reboot, whether the image came up or not, returns to the committed
           partition.
    
        
    Committing makes the running image the default, so it is what every
           later reboot comes back to.
    
        
    A committed image that later fails keeps booting itself: there is no
           trial left to fall back from. Check that it registers and carries
           traffic before you commit to it.
    
      
    

      
    
        
    Load a new image
    
        
    
          
          
        
    
        
    Uploading only stages it in RAM. Writing it to a partition is a separate step.
    
        
    
        
    
        
    
          How a trial boot works
          
    Trying a partition boots it once, with the hardware
             watchdog armed. If the image does not come up, the stick returns by
             itself to whichever partition is committed — no console, no
             intervention. A trial that boots fine still reverts at the next
             reboot, so committing to it is a separate decision you make after seeing
             it work.
    
          
    Writing takes about eighty seconds and runs on the stick by itself:
             this page follows it, and closing the page does not stop it. Do not
             power the stick off until it says written.
    
          
    /tmp is a RAM disk sharing
             27 MB with everything else running,
             so the image sits there only until it is written. The updater checks
             the md5 of both the kernel and the root filesystem before it erases
             anything.
    
        
    
        
    
          What the OLT is told about the version
          
    On this image the OLT is told 0.0.0 for both software
             images, whatever the partitions hold, unless the ONU identity switch
             on Config is on — then it is told OMCI_SW_VER1 for
             image 0 and OMCI_SW_VER2 for image 1. Both keys are
             shared with the stock firmware, which may rewrite them when it
             boots.

          Where it is kept, and what erases it
          
    In /etc/config/confd.auth, which is created here if it

          Locked out? The safe mode
          
    What it is. A recovery boot. For that one boot the fibre (PON) is off, so there is
             no internet through this stick and it does not disturb the line; the host port runs
             auto-negotiation, and a setting that forced it off is cleared; this page accepts
             admin / admin and root over SSH accepts the password
             admin. The saved password and SSH keys are unchanged: they come back at the next boot.
    
          
    How to leave it. If you lost your password, set a new one here (or add an SSH key):
             it is saved and takes effect from the next boot. Acknowledge the banner, then reboot. The next
             boot uses the saved configuration again, with the fibre on.
    
          
    How to enter it. Plug the stick in, wait about 80 seconds, pull it, wait a few
             seconds. Do that five times in a row (three times when the host port is set to auto-negotiation
             off), then plug it in and leave it in: that boot is the safe mode. Do not pull it again. Each
             power-up has to end roughly 60 to 110 seconds after power-on (the stick spends about
             54 seconds before its kernel starts; that can vary by board).
    
          
    The trade-off. Anyone who can power-cycle the stick can do this, and gets
             the default password for that boot.

          How keys are stored
          
    One OpenSSH line each, as ssh-keygen prints them. They are
             the way in on this image: its root password is fixed per build. Kept
             in /etc/config/dropbear.d/authorized_keys, beside the host
             key, so they survive a firmware reflash. dropbear reads the file on
             every login, so nothing restarts.

          Why this is not flash_eraseall
          
    Reset merges the image defaults, /etc/config_default.xml,
             into the service store with flash default cs; the LOID keys
             then take effect when OMCI is applied. It rewrites the named keys
             rather than erasing the partition, so GPON_SN,
             MAC_KEY, ELAN_MAC_ADDR and this page’s
             credential survive. flash_eraseall /dev/mtd3 — the
             recipe every forum thread gives — takes all of it, and is why
             people end up with sticks that never get past O0.
    
        
    
        
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    Kernel log
    
          
          
        
    
        
    The ring buffer the kernel and the boot scripts write to. To keep daemon logs, set a
           remote syslog server.
    
        
    
        
    
          How it is read
          
    With klogctl, which reads the buffer without consuming it
             — cat /proc/kmsg would eat the history and then
             block. The daemons also log to /var/log/omcid.log and
             /var/log/services.log, in RAM, over SSH, and to the
             remote syslog server when one is set.

           and MAC are kept. Takes a few seconds.
