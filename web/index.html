      Why this device behaves this way
      
    
        
    The kernel ring buffer is the whole log
    
        
    There is no syslog daemon in the image and no dmesg in
           its busybox, so the switch and OMCI complaints live in the ring buffer
           until they scroll away. This reads it without consuming it —
           cat /proc/kmsg would eat the history and then block.
    
      
    
      
    
        
    Addresses only, never names
    
        
    With no route to a resolver, a name lookup would hang rather than
           fail, and this daemon serves one request at a time. What a ping
           actually answers here is whether the management path works in both
           directions — worth knowing when this page loads but a scrape
           does not.

      Why this device behaves this way
      
    
        
    What a restore is allowed to write
    
        
    Every value goes through the same validation the Config tab’s
           fields use, so the SerDes keys stay refused. The identity keys need the tick box:
           a backup restored onto a different stick would otherwise
           overwrite the serial number and MAC key its line authenticates on.
    
      
    
      
    
        
    Why this is not flash_eraseall
    
        
    Reset runs the vendor’s own flash default cs, which
           rewrites the stored configuration rather than erasing the partition.
           GPON_SN, MAC_KEY and
           ELAN_MAC_ADDR survive it, and so does the credential
           this UI signs you in with. flash_eraseall /dev/mtd3 — the recipe
           every forum thread gives — takes all of it, and is why people
           end up with sticks that never get past O0.
    
      
    
      
    
        
    Where the credential is kept
    
        
    In /etc/config/confd.auth, which is created here if it
           does not exist yet, and which survives reflashing. A factory reset
           erases it and the page falls back to admin /
           admin until you set one again.

    Loading a new image
    
    
    
      
      
    
    
    
    Upload the tarball make image produced,
       then write it to the partition this stick is not running.
       Uploading is safe and repeatable; writing is the step that matters, which
       is why it is a separate button.

    Writing takes about eighty seconds, and this
       page answers nothing at all while it runs. Do not reload, and do not power
       the stick off.
    
    
    
      Doing it from a shell instead
      
    
    
    

    
    How a trial boot works
    
    
    Trying a partition boots it once, with
       the hardware watchdog armed. If the image does not come up, the stick
       returns by itself to whichever partition is kept — no console, no
       intervention. A trial that boots fine still reverts at the next reboot, so
       keeping it is a separate decision you make after seeing it work.
    
    
    

    
    
      Why this device behaves this way
      
    
        
    Where the upload is held
    
        
    /tmp is a RAM disk sharing
           27 MB with everything else running, so
           the image sits there only until it is written. The updater checks the
           md5 of both the kernel and the root filesystem before it erases
           anything, and streams each straight to flash, so it needs no scratch
           space beyond the tarball itself.
    
      
    
      
    
        
    What the OLT is told about the version
    
        
    On this base chk_swver_fix.sh copies the partition
           version into OMCI_SW_VER1/2 at every boot, but only when
           OMCI_OLT_MODE is neither 0 nor 21. Setting
           sw_custom_version0 or sw_custom_version1 in
           the U‑Boot environment makes the script prefer that string
           instead, and it survives reflashing — the supported answer to
           “my OMCI software version resets at every boot”. The
           widely repeated answer, OMCI_OLT_MODE=21, is one that
           script’s own comment calls a hack that segfaults
           checkomci. Nothing on this page writes any of it:
           changing the version an ISP authenticates against is a decision to
           make from a shell, on a line you can afford to lose —
           nv setenv sw_custom_version0 <string>.
