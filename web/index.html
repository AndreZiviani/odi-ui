Registration

    Forwarding

    Traffic crosses the switch in hardware, so these counters are the only place forwarding is visible. Healthy looks like a mirror: what the fibre receives, the host side sends. Rates are measured between refreshes — the running totals cannot be compared, because the performance-monitoring cycle clears the host side every fifteen minutes and leaves the fibre side alone.

    Learned addresses

    Which MAC addresses the switch has seen, and on which side. The counters above say whether frames cross; this says who is crossing.

    Restore
    
    
    Pick a backup file. Nothing is written until you have seen
       what differs. Values go through the same checks as the fields above, so
       the SerDes keys stay refused and the identity keys need the tick box
       — a backup restored onto a different stick would otherwise
       overwrite the serial number and MAC key that line authenticates on.
    
    
    
      
      
      
    
    
    
    

    
    Reset
    
    
    Resetting puts the service configuration
       back to the image defaults — VLAN, management IP, device mode, the
       OMCI settings. It runs the vendor's own flash default cs,
       which rewrites the stored config rather than erasing the partition, so
       GPON_SN, MAC_KEY and ELAN_MAC_ADDR
       are untouched and so is this page's password. That is the difference
       between this and flash_eraseall /dev/mtd3, the recipe every
       forum thread gives, which takes all of it and is why people end up with
       sticks that never get past O0.
    
    
    It does clear the PLOAM password, which some lines
       authenticate on, and it puts the management IP back to
       192.168.1.1 — so the page offers to restore that
       before you reboot, which is the step that is easy to forget and hard to
       undo. A backup downloads automatically before anything is written; the
       reset does not start until your browser has the file. Takes effect at the
       next reboot.
    
    
    
      
    
    
    
    

    
    Config UI password
    
    
    The credential for this page only — not the SSH or
       telnet login, and not anything the OLT sees. It is stored in
       /etc/config/confd.auth, which is created here if it does not
       exist yet, and it survives reflashing. A factory reset erases it, and the
       page goes back to admin / admin until you set
       one again.

    Loading a new image
    
    
    Uploading is still a shell job — the image is about
       3 MB and this daemon would have to hold it in memory the device does
       not have. Build it, copy it over, check it arrived intact, then write it
       to the partition you are not running:
    

    
    
    Then come back here and press Try on that partition. Do not
       reach for Keep first: the whole value of the trial is that the stick
       recovers on its own if the image is bad.
    
    
    /tmp is a RAM disk sharing
       27 MB with everything else running, so the
       copy is tight but fits — the page cache gives way. The updater
       checks the md5 of both the kernel and the root filesystem before it
       erases anything, and streams each straight to flash, so it needs no
       scratch space beyond the tarball itself.
    

    
    What the OLT is told
    
    
    The version beside each partition is what the updater wrote
       from that image. It is not automatically what your ISP sees: on
       this base, chk_swver_fix.sh copies it into
       OMCI_SW_VER1/2 at every boot, but only when
       OMCI_OLT_MODE is neither 0 nor 21. Setting
       sw_custom_version0 or sw_custom_version1 in the
       U‑Boot environment makes the script prefer that string instead, and
       it survives reflashing — which is the supported answer to
       “my OMCI software version resets at every boot”. The widely
       repeated answer, OMCI_OLT_MODE=21, is one that script’s
       own comment calls a hack that segfaults checkomci.
    
    
    Nothing here writes it. Changing the version an ISP
       authenticates against is a decision to make deliberately, from a shell,
       on a line you can afford to lose:
       nv setenv sw_custom_version0 <string>.
    

    
    How a trial boot works
    
    
    Trying a partition boots it once, with the
       hardware watchdog armed. If the image does not come up, the stick returns
       by itself to whichever partition is kept — no console, no
       intervention. A trial that boots fine still reverts on the next reboot,
       so keeping it is a separate decision you make after seeing it work.
